# Hyprland Configuration

**Last Updated**: 18/08/2026
**Version**: 1.0.0
**Maintained By**: Development Team
**Language**: British English (en_GB)
**Timezone**: Europe/London

---
Modular Hyprland configuration with base settings and device-specific overrides,
written for the **Hyprland 0.56 Lua config provider**.

Hyprland 0.56 ships two config providers: the original hyprlang `.conf` parser and
a Lua provider. This repository uses the Lua provider, so every file here is a
`.lua` module that calls the `hl.*` API rather than a `.conf` file of hyprlang
keywords.

## Structure

```
config/hypr/
├── 00-vars.lua             # Shared Lua locals (replaces hyprlang `$mod`) — NOT auto-loaded
├── 10-base.lua             # Env vars, general, dwindle, master, misc, debug
├── 20-monitors.lua         # Monitor configuration
├── 30-input.lua            # Keyboard, mouse, touchpad, XWayland
├── 40-appearance.lua       # Decorations, rounding, blur, shadows, opacity
├── 50-animations.lua       # Animation curves (hl.curve) and leaves (hl.animation)
├── 60-keybinds.lua         # Keybindings
├── 70-windowrules.lua      # Window rules
├── 80-autostart.lua        # Startup applications (a "hyprland.start" handler)
├── devices/                # Device-specific overrides, deployed as 90-device.lua
│   ├── laptop-intel.lua    # Intel laptop (i5-10210U, 32GB)
│   ├── framework.lua       # Framework AMD (Ryzen + Radeon, 64GB)
│   └── devtower.lua        # AMD desktop (CPU + GPU, 64GB, Go XLR)
├── KEYBINDS.md             # Keybind cheat sheet (deployed to ~/.config/hypr/)
├── INTEGRATION.md          # How these files reach ~/.config/hypr
└── README.md               # This file
```

There is deliberately **no `hyprland.lua` in this repository**. Under the Lua
provider, Home Manager generates `~/.config/hypr/hyprland.lua` itself — it is the
entry point and it must not be hand-written. The old `hyprland.conf` "source = …"
manifest has no successor here.

## Load Order

Home Manager writes each file above to `~/.config/hypr/<name>.lua`, prepends
`~/.config/hypr` to Lua's `package.path`, and then emits one `require()` per file
in the generated `hyprland.lua`:

```lua
-- Generated by Home Manager.
local hm_xdg_config_home = os.getenv("XDG_CONFIG_HOME") or "/home/<user>/.config"
package.path = hm_xdg_config_home .. "/hypr/?.lua;" .. hm_xdg_config_home .. "/hypr/?/init.lua;" .. package.path

require("10-base")
require("20-monitors")
…
require("90-device")
```

The `require()` calls are emitted in **alphabetical order** of the attribute name.
The two-digit prefixes exist so that lexicographic order and the intended numeric
order agree: `10-` … `80-`, with the device file last as `90-device`. Do not rename
these files to bare words — doing so silently reshuffles the load order.

`00-vars.lua` is the one exception: it is registered with `autoLoad = false`, so
Hyprland never executes it on its own. It returns a table and other files pull it
in explicitly:

```lua
local vars = require("00-vars")
hl.bind(vars.mod .. " + Q", hl.dsp.window.close())
```

This replaces hyprlang's `$mod = SUPER` variable mechanism, which the Lua provider
has no equivalent for.

Because the device file is required last, anything it sets wins over the shared
defaults. `hl.config()` **merges** rather than replaces: it writes only the leaf
keys it is given, so a device file can lower `decoration.blur.size` without
disturbing the rest of `decoration`.

## Usage

### With Home Manager (Recommended)

`home/modules/hyprland.nix` sets `configType = "lua"` and lists these files under
`wayland.windowManager.hyprland.extraLuaFiles`. Each device's `home/*.nix` adds its
own `extraLuaFiles."90-device"` entry pointing at the right `devices/*.lua`.

After a rebuild, the deployed configuration lives at:
- `~/.config/hypr/hyprland.lua` (generated by Home Manager — the entry point)
- `~/.config/hypr/{00-vars,10-base,…,80-autostart,90-device}.lua` (these files)
- `~/.config/hypr/KEYBINDS.md` (cheat sheet, read by `SUPER + /`)

See `INTEGRATION.md` for the full mechanism.

### Manual Usage (Standalone)

To use these files without Home Manager, copy or symlink them into
`~/.config/hypr/` and write your own entry point:

1. **Link the modules:**
   ```bash
   mkdir -p ~/.config/hypr
   ln -sf ~/Repos/personal/nix-config/config/hypr/[0-9]*.lua ~/.config/hypr/
   # Pick your device file and give it the 90-device name:
   ln -sf ~/Repos/personal/nix-config/config/hypr/devices/laptop-intel.lua \
          ~/.config/hypr/90-device.lua
   ```

2. **Create `~/.config/hypr/hyprland.lua`:**
   ```lua
   local home = os.getenv("XDG_CONFIG_HOME") or (os.getenv("HOME") .. "/.config")
   package.path = home .. "/hypr/?.lua;" .. package.path

   require("10-base")
   require("20-monitors")
   require("30-input")
   require("40-appearance")
   require("50-animations")
   require("60-keybinds")
   require("70-windowrules")
   require("80-autostart")
   require("90-device")
   ```
   Do **not** require `00-vars` here — it is a module, pulled in by the files that
   need it.

3. **Reload Hyprland:**
   ```bash
   hyprctl reload
   ```

## Customisation

### Base Configuration

All shared settings live in the numbered files:
- **10-base.lua**: environment variables, `general`, `dwindle`, `master`, `misc`, `debug`
- **20-monitors.lua**: default catch-all monitor (`output = ""`)
- **30-input.lua**: keyboard layout, mouse, touchpad, XWayland scaling
- **40-appearance.lua**: rounding, opacity, blur, shadows
- **50-animations.lua**: `hl.curve()` bezier definitions and `hl.animation()` leaves
- **60-keybinds.lua**: all keyboard and mouse bindings
- **70-windowrules.lua**: float, opacity and workspace rules
- **80-autostart.lua**: the `hl.on("hyprland.start", …)` handler

### Device-Specific Overrides

Each device file may override anything, and is loaded last:
- **laptop-intel.lua**: single eDP-1 display, battery-tuned blur, workspace-1 dashboard, dual keyboard layouts
- **framework.lua**: high-DPI scaling, AMD GPU tuning, creative workflow
- **devtower.lua**: multi-monitor, desktop performance, Go XLR

## Key Features

The authoritative list is `KEYBINDS.md` (also viewable in-session with `SUPER + /`).
Highlights:

### Vim-Style Navigation
- `SUPER + H/J/K/L`: move focus between windows (arrow keys work too)
- `SUPER + SHIFT + H/J/K/L`: move windows

### Workspaces
- `SUPER + 1-9, 0`: switch to workspace 1-10
- `SUPER + SHIFT + 1-9, 0`: move window to workspace 1-10
- `SUPER + S`: toggle scratchpad (special workspace)
- `SUPER + scroll`: cycle workspaces

### Applications
- `SUPER + Return`: terminal (kitty)
- `SUPER + Space`: app launcher (wofi)
- `SUPER + W`: Zen browser (`SHIFT` Brave, `ALT` LibreWolf, `CTRL` Firefox Developer Edition)
- `SUPER + F`: file manager (Thunar)
- `SUPER + Z`: Zed editor

### Window Management
- `SUPER + Q`: close window
- `SUPER + V`: toggle floating
- `SUPER + F11`: fullscreen
- `` SUPER + ` ``: toggle split direction (dwindle)

### Screenshots
- `Print`: region screenshot (slurp + swappy)
- `SUPER + Print`: full-screen screenshot (swappy)

### Laptop Controls
- `XF86AudioRaiseVolume`/`LowerVolume`: volume
- `XF86AudioMute`, `XF86AudioMicMute`: mute toggles
- `XF86MonBrightnessUp`/`Down`: brightness

## Integration with Home Manager

`home/modules/hyprland.nix` provides:

Device-specific settings are in:

- `home/devtower*.nix` (devtower)

## Editor Support

Hyprland ships LuaLS type stubs for the `hl.*` API at
`<hyprland-package>/share/hypr/stubs/hl.meta.lua`. `home/modules/hyprland.nix`
writes `~/.config/hypr/.luarc.json` pointing at them, with `diagnostics.globals =
["hl"]`, so lua-language-server offers completion and catches typos in these files.

The stubs are the authoritative API reference. Prefer them over the wiki when the
two disagree.

## Tips

1. **Syntax-check a file before rebuilding:**
   ```bash
   luac -p config/hypr/60-keybinds.lua
   ```

2. **Reload the deployed config:**
   ```bash
   hyprctl reload
   ```

3. **Change a setting at runtime** — `hyprctl keyword` does **not** work under the
   Lua provider. Use `hyprctl eval` instead:
   ```bash
   hyprctl eval 'hl.config({ general = { border_size = 10 } })'
   ```

4. **Run a dispatcher at runtime** — the legacy flat names are gone; pass a Lua
   expression:
   ```bash
   hyprctl dispatch "hl.dsp.window.close()"
   hyprctl dispatch "hl.dsp.dpms('on')"
   ```

5. **Confirm which provider is active:**
   ```bash
   hyprctl status   # prints e.g. `configProvider: lua`
   ```

6. **Monitor and window info:**
   ```bash
   hyprctl monitors
   hyprctl clients
   hyprctl devices
   ```

7. **Debug issues:**
   ```bash
   journalctl --user -u hyprland.service
   ```
