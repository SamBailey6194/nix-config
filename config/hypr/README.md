# Hyprland Configuration

**Last Updated**: 28/09/2026
**Version**: 1.2.0
**Maintained By**: Development Team
**Language**: British English (en_GB)
**Timezone**: Europe/London

---
Modular Hyprland configuration with base settings and device-specific overrides,
written for the **Hyprland 0.56 Lua config provider**.

Hyprland 0.56 ships two config providers: the original hyprlang `.conf` parser and
a Lua provider. This repository uses the Lua provider, so every file here is a
`.lua` module that calls the `hl.*` API rather than a `.conf` file of hyprlang
keywords.

## Structure

```
config/hypr/
├── 00-vars.lua             # Shared Lua locals (replaces hyprlang `$mod`) — NOT auto-loaded
├── 10-base.lua             # Env vars, general, dwindle, master, misc, debug
├── 20-monitors.lua         # Monitor configuration
├── 30-input.lua            # Keyboard, mouse, touchpad, XWayland
├── 40-appearance.lua       # Decorations, rounding, blur, shadows, opacity
├── 50-animations.lua       # Animation curves (hl.curve) and leaves (hl.animation)
├── 60-keybinds.lua         # Keybindings
├── 70-windowrules.lua      # Window rules
├── 80-autostart.lua        # Startup applications (a "hyprland.start" handler)
├── devices/                # Device-specific overrides, deployed as 90-device.lua
│   ├── laptop-intel.lua    # Intel laptop (i5-10210U, 32GB)
│   ├── devtower-intel.lua  # Intel desktop: three monitors, 40 workspaces
│   ├── devtower-intel-dashboard.lua  # devtower-intel's ws1 dashboard and ws2 terminal grid
│   ├── framework.lua       # Framework AMD (Ryzen + Radeon, 64GB)
│   └── devtower.lua        # AMD desktop (CPU + GPU, 64GB, Go XLR)
├── KEYBINDS.md             # Keybind cheat sheet (deployed to ~/.config/hypr/)
├── KEYBINDS-devtower-intel.md  # devtower-intel's sheet (replaces KEYBINDS.md there)
├── INTEGRATION.md          # How these files reach ~/.config/hypr
└── README.md               # This file
```

There is deliberately **no `hyprland.lua` in this repository**. Under the Lua
provider, Home Manager generates `~/.config/hypr/hyprland.lua` itself — it is the
entry point and it must not be hand-written. The old `hyprland.conf` "source = …"
manifest has no successor here.

## Load Order

Home Manager writes each file above to `~/.config/hypr/<name>.lua`, prepends
`~/.config/hypr` to Lua's `package.path`, and then emits one `require()` per file
in the generated `hyprland.lua`:

```lua
-- Generated by Home Manager.
local hm_xdg_config_home = os.getenv("XDG_CONFIG_HOME") or "/home/<user>/.config"
package.path = hm_xdg_config_home .. "/hypr/?.lua;" .. hm_xdg_config_home .. "/hypr/?/init.lua;" .. package.path

require("10-base")
require("20-monitors")
…
require("90-device")
```

The `require()` calls are emitted in **alphabetical order** of the attribute name.
The two-digit prefixes exist so that lexicographic order and the intended numeric
order agree: `10-` … `80-`, with the device file last as `90-device`. Do not rename
these files to bare words — doing so silently reshuffles the load order.

`00-vars.lua` is the one exception: it is registered with `autoLoad = false`, so
Hyprland never executes it on its own. It returns a table and other files pull it
in explicitly:

```lua
local vars = require("00-vars")
hl.bind(vars.mod .. " + Q", hl.dsp.window.close())
```

This replaces hyprlang's `$mod = SUPER` variable mechanism, which the Lua provider
has no equivalent for.

Because the device file is required last, anything it sets wins over the shared
defaults. `hl.config()` **merges** rather than replaces: it writes only the leaf
keys it is given, so a device file can lower `decoration.blur.size` without
disturbing the rest of `decoration`.

## Workspace Map

Workspaces are not interchangeable — most of them have a fixed purpose, enforced
by the window rules in `70-windowrules.lua` and, for the laptop, re-asserted in
`devices/laptop-intel.lua`. This is the default map, used by laptop-intel;
devtower-intel replaces it with forty workspaces (see
[devtower-intel](#devtower-intel) below):

| Workspace | Contents                      | Assigned by                                                 |
|-----------|-------------------------------|-------------------------------------------------------------|
| `1`       | Dashboard (keybinds + btop)   | Device file (laptop only)                                   |
| `2`       | nix-config dev layout         | Window rules (class + title for Zed, class only for Neovim) |
| `3-5`     | Dev pool, allocated as needed | Window rules registered at launch                           |
| `6`       | Mail (aerc + sheet, Claws)    | `00-vars.lua` workspaceAssignments                          |
| `7`       | Browsers                      | Window rules (class match)                                  |
| `8`       | Affinity Suite                | Window rules (class match)                                  |
| `9`       | Comms (Teams, Zoom)           | Window rules (class match)                                  |
| `10`      | Everything else               | Catch-all rule (laptop only)                                |

The "Assigned by" column is the **mechanism**, not the trigger — the two are
worth keeping apart:

- Workspace 2 is **reserved**, and `SUPER + SHIFT + Z` is only what *launches*
  the nix-config layout. It does not place it. The windows land on workspace 2
  because static rules match them there: the editor on class **and** title
  (Zed has no `--class`, so its title — the folder name `nix-config` — is the
  only distinguishing feature). Zed is the layout's only window: it launches
  no Kitty terminals beside it and fills the workspace. Rename the repository
  folder and the editor rule stops firing; see `00-vars.lua`.
  The Neovim variant, `SUPER + SHIFT + Return`, is a single Kitty window matched
  on the class `nixcfg-nvim` alone, so it does not depend on the folder name.
  The keybind reference, file tree, git panel and shell are panes and tabs
  inside Neovim, and the window fills the workspace.
- Static window rules cannot express "the next free workspace", so `SUPER +
  CTRL + Z` picks the workspace at runtime and then registers the *same kind*
  of class+title rule workspace 2 uses, via `hyprctl eval`, immediately before
  launching. It beats the catch-all by being registered later — the last
  matching rule wins. `SUPER + CTRL + Return` does the same for Neovim with a
  single class-only rule, on the per-workspace class `devpool-nvim-N`.

  It deliberately does **not** use `hl.exec_cmd(cmd, { workspace = ... })`.
  Per-launch exec rules attach by matching the spawned PID, and `zeditor` is a
  single-instance CLI: when Zed is already running it forwards the request over
  IPC and exits, so the new window belongs to a process Hyprland never spawned
  and the rule never attaches. The editor would silently land on the catch-all.
  That registered rule, not the keybind, is what does
  the placing.
- The 3-5 dev pool is **laptop-only in practice today**. `60-keybinds.lua` is
  shared by every device, but `devices/devtower.lua` pins DaVinci Resolve to
  workspace 5 and OBS to workspace 6, and `devices/framework.lua` pins Resolve
  to workspace 5 — all inside the pool. On those machines a generic dev layout
  would be handed a workspace that a creative application already claims. Both
  device files carry a comment recording this; settle it before enabling the
  pool there.

### devtower-intel

`devices/devtower-intel.lua` replaces the map above with forty workspaces over
three monitors: left (4K, scale 1.5), centre (1440p) and right (1080p,
portrait), plus overflow workspaces from 41 up. laptop-intel is unaffected.

| Workspace | Contents                                                             | Monitor |
|-----------|----------------------------------------------------------------------|---------|
| `1`       | Dashboard (keybinds, btop, nvtop)                                    | right   |
| `2`       | Four Kitty terminals in a 2x2 grid (commands, SSH)                   | centre  |
| `3`       | File managers (Yazi, Thunar)                                         | centre  |
| `4`       | Mail (aerc + sheet, Claws)                                           | centre  |
| `5-10`    | LibreOffice Writer, Calc, Impress, Draw, Math, Base                  | centre  |
| `11`      | Comms (Teams, Zoom)                                                  | centre  |
| `12`      | Zen                                                                  | left    |
| `13`      | LibreWolf                                                            | left    |
| `14`      | Firefox Developer Edition                                            | centre  |
| `15`      | Brave                                                                | centre  |
| `16`      | Video and image viewers (VLC, mpv, imv)                              | left    |
| `17-19`   | Affinity Designer, Photo, Publisher                                  | centre  |
| `20`      | DaVinci Resolve                                                      | left    |
| `21-25`   | PhotoCraft, VectorCraft, LightCraft, PdfCraft, DesignCraft           | centre  |
| `26-28`   | SoundCraft, WordCraft, DeckCraft                                     | centre  |
| `29-30`   | EffectCraft, FilmCraft                                               | left    |
| `31`      | nix-config dev layout                                                | centre  |
| `32-40`   | Dev pool, allocated as needed                                        | centre  |
| `41+`     | Unassigned windows, each on the first free workspace                 | centre  |

- **Keys**: `SUPER + 1-9, 0` switches to 1-10, `SUPER + SHIFT` to 11-20,
  `SUPER + CTRL` to 21-30 and `SUPER + ALT` to 31-40.
- **Moving a window**: `SUPER + SHIFT + number` no longer moves (it is unbound
  and reused for 11-20). Press `SUPER + period` to enter the `move-window`
  submap, then the number with the bank's modifier minus `SUPER` (`1` → 1,
  `SHIFT + 1` → 11, `CTRL + 1` → 21, `ALT + 1` → 31). The submap resets after
  one move; `Escape` cancels.
- **Login terminals**: `devices/devtower-intel-dashboard.lua` builds the ws1
  dashboard and the ws2 terminal grid at login, as floating rectangles pinned
  to their workspace. `SUPER + Escape` (ws1) and `SUPER + SHIFT + Escape` (ws2)
  focus the group, reopen closed panes and gather strays. The ws2 terminals
  run the login shell in `$HOME` under the classes `ws2-term-1` to `ws2-term-4`.
  The same login handler opens Yazi on ws3, aerc with its keybind sheet on ws4
  and Teams on ws11, each with a per-launch `"<n> silent"` rule so focus stays
  on ws2.
- **Unassigned windows**: the catch-all parks them on the hidden
  `special:unassigned` workspace; a `window.open` handler then moves each to the
  lowest workspace from 41 up that holds no windows, and focus follows. A
  floating dialog instead joins a window of the same process (preferring the
  active workspace), so it opens over the app that asked.
- **Mail** moves to workspace 4: the device file sets `vars.mailWorkspace = 4`,
  which the `SUPER + E` mail layout in `60-keybinds.lua` reads.
- **Dev layouts**: the device file exports `DEV_LAYOUT_NIX_CONFIG_WS=31`,
  `DEV_LAYOUT_POOL_FIRST=32` and `DEV_LAYOUT_POOL_LAST=40` with `hl.env`, so
  `dev-layout` (which inherits Hyprland's environment through the keybinds)
  places nix-config on 31 and allocates from 32-40. No creative application
  sits in that pool here.
- **Keybind sheet**: `KEYBINDS-devtower-intel.md`, deployed by
  `home/devtower-intel.nix` as `~/.config/hypr/KEYBINDS.md` in place of the
  laptop sheet, so `SUPER + /` and the ws1 dashboard show the right keys.

## Usage

### With Home Manager (Recommended)

`home/modules/hyprland.nix` sets `configType = "lua"` and lists these files under
`wayland.windowManager.hyprland.extraLuaFiles`. Each device's `home/*.nix` adds its
own `extraLuaFiles."90-device"` entry pointing at the right `devices/*.lua`.

After a rebuild, the deployed configuration lives at:
- `~/.config/hypr/hyprland.lua` (generated by Home Manager — the entry point)
- `~/.config/hypr/{00-vars,10-base,…,80-autostart,90-device}.lua` (these files)
- `~/.config/hypr/KEYBINDS.md` (cheat sheet, read by `SUPER + /`)

See `INTEGRATION.md` for the full mechanism.

### Manual Usage (Standalone)

To use these files without Home Manager, copy or symlink them into
`~/.config/hypr/` and write your own entry point:

1. **Link the modules:**
   ```bash
   mkdir -p ~/.config/hypr
   ln -sf ~/Repos/personal/nix-config/config/hypr/[0-9]*.lua ~/.config/hypr/
   # Pick your device file and give it the 90-device name:
   ln -sf ~/Repos/personal/nix-config/config/hypr/devices/laptop-intel.lua \
          ~/.config/hypr/90-device.lua
   ```

2. **Create `~/.config/hypr/hyprland.lua`:**
   ```lua
   local home = os.getenv("XDG_CONFIG_HOME") or (os.getenv("HOME") .. "/.config")
   package.path = home .. "/hypr/?.lua;" .. package.path

   require("10-base")
   require("20-monitors")
   require("30-input")
   require("40-appearance")
   require("50-animations")
   require("60-keybinds")
   require("70-windowrules")
   require("80-autostart")
   require("90-device")
   ```
   Do **not** require `00-vars` here — it is a module, pulled in by the files that
   need it.

3. **Reload Hyprland:**
   ```bash
   hyprctl reload
   ```

## Customisation

### Base Configuration

All shared settings live in the numbered files:
- **10-base.lua**: environment variables, `general`, `dwindle`, `master`, `misc`, `debug`
- **20-monitors.lua**: default catch-all monitor (`output = ""`)
- **30-input.lua**: keyboard layout, mouse, touchpad, XWayland scaling
- **40-appearance.lua**: rounding, opacity, blur, shadows
- **50-animations.lua**: `hl.curve()` bezier definitions and `hl.animation()` leaves
- **60-keybinds.lua**: all keyboard and mouse bindings
- **70-windowrules.lua**: float, opacity and workspace-assignment rules
- **80-autostart.lua**: the `hl.on("hyprland.start", …)` handler

### Device-Specific Overrides

Each device file may override anything, and is loaded last:
- **laptop-intel.lua**: single eDP-1 display, battery-tuned blur, workspace-1 dashboard, dual keyboard layouts
- **devtower-intel.lua**: three monitors, the 40-workspace map, the 41+ overflow for unassigned windows, four workspace keybind banks, the `move-window` submap and `SUPER + comma` to move the focused workspace between the centre and left monitors (see [devtower-intel](#devtower-intel)); its ws1 dashboard and ws2 terminal grid are `devtower-intel-dashboard.lua`
- **framework.lua**: high-DPI scaling, AMD GPU tuning, creative workflow
- **devtower.lua**: multi-monitor, desktop performance, Go XLR

## Key Features

The authoritative list is `KEYBINDS.md` (also viewable in-session with `SUPER + /`).
Highlights:

### Vim-Style Navigation
- `SUPER + H/J/K/L`: move focus between windows (arrow keys work too)
- `SUPER + SHIFT + H/J/K/L`: move windows

### Workspaces
- `SUPER + 1-9, 0`: switch to workspace 1-10
- `SUPER + SHIFT + 1-9, 0`: move window to workspace 1-10 (devtower-intel:
  switch to 11-20; moving uses `SUPER + period` — see
  [devtower-intel](#devtower-intel))
- `SUPER + S`: toggle scratchpad (special workspace)
- `SUPER + scroll`: cycle workspaces
- Each workspace has a fixed purpose — see [Workspace Map](#workspace-map)

### Applications
- `SUPER + Return`: terminal (kitty)
- `SUPER + Space`: app launcher (wofi)
- `SUPER + W`: Zen browser (`SHIFT` Brave, `ALT` LibreWolf, `CTRL` Firefox Developer Edition)
- `SUPER + F`: file manager (Thunar)
- `SUPER + Z`: Zed editor
- `SUPER + SHIFT + Z`: nix-config dev layout on workspace 2 (31 on devtower-intel)
- `SUPER + CTRL + Z`: generic dev layout on the next free workspace (3-5;
  32-40 on devtower-intel).
  Goes through the `dev-layout-pick` wofi picker (declared in
  `home/modules/hyprland.nix`), because dev-layout needs a project path and a
  keybind inherits Hyprland's working directory rather than a project's. From a
  terminal, `dev-layout --new [--nvim] <path>` skips the picker.
- `SUPER + SHIFT + Return`: nix-config layout, Neovim alone, on workspace 2
  (31 on devtower-intel)
- `SUPER + CTRL + Return`: dev layout, Neovim alone, on the next free workspace
  (3-5; 32-40 on devtower-intel), through the same picker
- `SUPER + ALT + Return`: Neovim in a plain Kitty window. No dev-layout rule
  claims it, so it lands wherever an ordinary window would: on the laptop the
  catch-all sends it, silently, to workspace 10 (on devtower-intel, the first
  free workspace from 41 up, which takes focus), not the workspace you pressed
  the key on. A bare `nvim` builds the same
  in-editor layout (keybind reference, file tree, terminal tab, and the git
  panel inside a git work tree) wherever it starts, as far as the window's width allows; the RETURN layouts
  only add the workspace placement and the full width.

### Window Management
- `SUPER + Q`: close window
- `SUPER + V`: toggle floating
- `SUPER + F11`: fullscreen
- `` SUPER + ` ``: toggle split direction (dwindle)

### Screenshots
- `Print`: region screenshot (slurp + swappy)
- `SUPER + Print`: full-screen screenshot (swappy)

### Laptop Controls
- `XF86AudioRaiseVolume`/`LowerVolume`: volume
- `XF86AudioMute`, `XF86AudioMicMute`: mute toggles
- `XF86MonBrightnessUp`/`Down`: brightness

## Editor Support

Hyprland ships LuaLS type stubs for the `hl.*` API at
`<hyprland-package>/share/hypr/stubs/hl.meta.lua`. `home/modules/hyprland.nix`
writes `~/.config/hypr/.luarc.json` pointing at them, with `diagnostics.globals =
["hl"]`, so lua-language-server offers completion and catches typos in these files.

When this repository itself is open in Zed or Neovim, lua-language-server's
workspace is the repository root, so it reads the checked-in `.luarc.json` there
instead. That file points at `/run/current-system/sw/share/hypr/stubs` (a
checked-in file cannot name a store path, and the system profile always has the
running Hyprland's stubs), adds `config/hypr/?.lua` to `runtime.path` so
`require("00-vars")` resolves, and declares `hl` and `vim` as globals. It needs a
host with Hyprland installed system-wide.

The stubs are the authoritative API reference. Prefer them over the wiki when the
two disagree.

## Tips

1. **Syntax-check a file before rebuilding:**
   ```bash
   luac -p config/hypr/60-keybinds.lua
   ```

2. **Reload the deployed config:**
   ```bash
   hyprctl reload
   ```

3. **Change a setting at runtime** — `hyprctl keyword` does **not** work under the
   Lua provider. Use `hyprctl eval` instead:
   ```bash
   hyprctl eval 'hl.config({ general = { border_size = 10 } })'
   ```

4. **Run a dispatcher at runtime** — the legacy flat names are gone; pass a Lua
   expression:
   ```bash
   hyprctl dispatch "hl.dsp.window.close()"
   hyprctl dispatch "hl.dsp.dpms('on')"
   ```

5. **Confirm which provider is active:**
   ```bash
   hyprctl status   # prints e.g. `configProvider: lua`
   ```

6. **Monitor and window info:**
   ```bash
   hyprctl monitors
   hyprctl clients
   hyprctl devices
   ```

7. **Debug issues:**
   ```bash
   journalctl --user -u hyprland.service
   ```
